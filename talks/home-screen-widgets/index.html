The one thing to remember

A widget is not a Flutter screen.

Your Flutter app

Runs when someone opens it. Flutter draws every pixel.

Your Dart code
Flutter can't draw here

The home screen

Run by the phone, not your app. Your widget stays on it even when your app is closed.

  • Register it in the app's manifest
  • Describe the widget's size in an XML file
  • Add Glance to Gradle and write the UI in Kotlin

Why this approach

Why generate native code?

Full control.

Two languages and two codebases to maintain.

You reuse your Flutter UI, but the widget only shows a picture.

The trade-off: a smaller set of building blocks.

How it works

Your app and your widget never talk directly.

Your app

saves

Shared storage

iOS: App Group
Android: SharedPreferences

read by widget

Your widget

Reads it whenever the phone redraws.

Pictures, like Dash, are saved as files in the same shared space.

Updating the widget

Save the data, then ask for a redraw.

// 1. Save what the widget should show
await StrideHomeWidget.saveData(
  steps: today.steps,
  goal: today.goal,
  streak: today.streak,
);

// 2. Ask the phone to redraw it
await StrideHomeWidget.updateWidget();
The phone decides when

A redraw is a request, not an order.

Apple: a widget people view often typically gets 40 to 70 refreshes a day.

Android: scheduled updates run at most once every 30 minutes.

developer.apple.com · developer.android.com

What I ran into

Android taught me the most.

Nothing was saved

home_widget saves files with the help of path_provider_android. Version 2.3 of it failed on my Android 10 phone, so no files were saved and the widget never redrew.

Fix: pinned 2.2.23

The wide widget was tiny

Android 12+ understands “4 × 2 cells”. Android 10 only reads a minimum width and height.

Fix: set minWidth and minHeight

What it can't do yet

Can I tick it off from the widget?

Not with the generator. Buttons still need native code.

  • iOS 17+: buttons and toggles through App Intents
  • Android: a Glance action
  • Both call back into Dart through home_widget's interactivity callback

Getting started

Your first widget in four steps.

1

Add the packages

home_widget as a dependency.

home_widget_generator and home_widget_cli as dev dependencies.

2

Describe the widget

A Dart file in a home_widget/ folder, with a class marked @HomeWidget.

3

Generate

dart run
home_widget_cli:home_widget
generate

Then a full flutter run.

4

Save, then redraw

saveData(...)
updateWidget()

On a real iPhone, the app and the widget share data through an App Group, and App Groups need a paid Apple Developer account. The iOS Simulator works without one.
